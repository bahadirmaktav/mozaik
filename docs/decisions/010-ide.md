# 010 — IDE module (V0.7)

Specification: local `.plans/tessera-v0.7-plan.md`. A first working IDE to evaluate the
layout and feature set; not a VS Code copy, and no build, run, debug or test runner.

## Panels, not a second workspace

The IDE is four built-in plugins in the ordinary workspace. There is no IDE window, no
inner tab bar and no inner split system:

| Plugin                                | Instance                                    | View                                                          |
| ------------------------------------- | ------------------------------------------- | ------------------------------------------------------------- |
| `ide` (IDE Project)                   | One project root (single root per panel)    | Explorer / Search / Results, Outline, server and problem line |
| `code` (Code Editor)                  | A text document (the shared document store) | CodeMirror with IDE extensions and a thin bar with ⋯ menu     |
| `problems`                            | Window-wide diagnostics                     | Diagnostics by file                                           |
| `diff` (Changes, not in the launcher) | A file path                                 | Read-only last commit ↔ current text                          |

Placement uses the existing model: the first file opened from a project splits the project
panel to the right with a narrow sidebar share (the `open` action gained an optional `ratio`);
later files become tabs in the last focused code panel; "Open to the Side" splits it. Problems
opens below the whole layout (`open` with `around: "root"`). Two files side by side are two
Tessera panels; the same document is never shown twice. These positions are a starting point
for review, as the plan asks.

## Editor

The Code Editor is a separate component from the Text Editor (`src/plugins/ide/CodeEditor.tsx`)
with line numbers, folding, bracket matching and closing, auto-indent, multiple selections
(Ctrl+click, Ctrl+D, Alt+drag rectangles), the CodeMirror search/replace panel, go to line,
lint markers and completion. Syntax comes from `@codemirror/language-data` (each language is
a lazy chunk), with an IDE highlight style readable on the dark background.

What is shared is deliberate and small: the **document store** (path, text, saved text,
revision, BOM, line endings, conflict), the theme and the native file commands. Therefore the
existing safety applies unchanged to code: explicit save, unsaved marker, close prompt,
recovery snapshots, watcher reload of clean documents and conflict for dirty ones, and one
document per file (opening a file already open in a Text Editor activates that tab).

Keys: CodeMirror's standard keymaps and the conventional keys of the LSP client package
(F12 definition, Shift+F12 references, F2 rename) inside the editor, with every action also in
the ⋯ / right-click menu. Bindings with Ctrl+Alt are removed because they are AltGr on many
layouts. This is not the deferred Tessera keymap; no workspace shortcut changed.

## Project explorer

A tree of the project root, folders first, loaded lazily per expanded folder through the
File Manager's listing and watch commands (`.git` hidden). New file/folder, rename (F2),
Trash after confirmation (Delete), and move by dragging onto a folder (refused on a name
conflict, never replaced). Open documents follow a rename or move. It is not the File Manager:
no permanent delete, copy/paste, sorting or hidden-file setting.

**Filtering**: the tree shows everything except `.git`. Quick open and project search honour
`.gitignore` (also outside Git repositories, via the `ignore` crate) and the project's exclude
patterns, and skip `.git`.

## Navigation and search

- **Go to file** (header button or ⋯): fuzzy ranking of the project's file list (up to 50,000
  files, Rust walk), favouring file names, word starts and runs.
- **Back / Forward**: jumps (definition, results, problems, outline, quick open) record where
  they started; up to 50 places per window. Buttons in the editor bar and menu.
- **Project search**: text or regular expression (Rust `regex` syntax), match case, whole
  word, within lines; files over 4 MiB, binary or non-UTF-8 files are skipped and counted;
  at most 5,000 matches. Columns are UTF-16, the editor's unit.
- **Replace All** asks first and states what happens: open documents change in their editors
  and stay unsaved (undoable); closed files are rewritten by Rust only if they still have the
  revision seen by the search, with encoding and line endings kept and an atomic replace. A
  changed file is reported and left alone. Open buffers get the replacement computed by the
  same Rust code, so `$1`/`${name}` groups mean the same everywhere.

## Language servers

**Native side** (`src-tauri/src/lsp.rs`): a server is started only by name (`clangd` is the
only one); the program is found on `PATH` or in the usual LLVM locations, or chosen by the
user in a native file dialog and stored in `language-servers.json`. The renderer can never pass
a program path or arguments. Processes are owned by their window, framed with
`Content-Length`, read on their own threads (stderr is drained; its last lines explain an
unexpected exit), and stopped by closing input, then killed after 1.5 s — on panel close,
window close and application exit. No console window on Windows. Arguments are none: clangd
reads the project's `compile_commands.json` and `.clangd` by itself, which keeps existing build
information usable without Tessera generating it.

**Renderer side** (`src/plugins/ide/lsp.ts`): `@codemirror/lsp-client` (pinned) provides the
JSON-RPC client, document synchronisation, completion, hover and signature help. Tessera adds:

- A workspace that keeps a file open on the server as long as its **document** is open, not
  just its view, because Tessera unmounts hidden tabs; reopening per tab switch would reparse
  and drop diagnostics.
- Diagnostics stored per file for Problems and the project status line; shown in the
  editor (lint markers, gutter) when a view attaches.
- Navigation (definition, declaration, implementation, references) that opens Tessera tabs and
  records history; several results go to the sidebar's Results view.
- **Workspace edits** (rename, quick fixes, server `workspace/applyEdit`): all files are
  validated first; open documents change in their editors (unsaved, undoable); files that are
  not open are listed in a confirmation, then saved with a revision check and atomic replace.
  Creating, renaming or deleting files from an edit is refused. The package's own rename only
  touches open files, so it is not used.
- Formatting (document, selection) applied only if the text did not change meanwhile; **format
  on save** per project, with a 3 s limit after which the file is saved unformatted (a save is
  never blocked by the formatter).
- Outline from `textDocument/documentSymbol`, refreshed 400 ms after typing. There is no
  second parser: without a server the outline says so.
- Server Markdown (hover, completion docs) is reduced to a fixed set of elements without
  attributes, links or images.

**Lifecycle**: the server for a project starts with the first C/C++ file opened in a Code
Editor of that project, not when the IDE opens. A missing or failed server is shown in the
project line with a Settings button and is not restarted in a loop; editing continues without
it. Files outside every open project get no server.

Download and version management of language servers is deferred as the plan says; the
settings only find or choose an installed program. Other servers fit by adding a `Server` kind
in Rust and an extension mapping in `paths.ts`.

## Git

`src-tauri/src/git.rs` runs only `rev-parse --show-toplevel`, `status --porcelain=v2 --branch
-z` and `cat-file` with `GIT_OPTIONAL_LOCKS=0` (no index refresh written), `core.fsmonitor`
off (a repository's fsmonitor hook is a program) and no filters or textconv. The header shows
the branch (or `detached at …`); the explorer colours modified, added, renamed, untracked and
conflicted files and marks folders containing changes; "Open Changes" shows the committed text
beside the current one (unsaved edits included) in a read-only merge view. Status refreshes on
disk changes in watched project folders or `.git`, after a project replace and on window focus. Without Git or outside a
repository nothing is shown. Staging, commits and other writes are out of scope.

## Project settings

Stored by Rust per canonical project root in `ide-projects.json` in the app config directory —
never inside the user's repository, and never able to change which programs run: format on
save, tab size, spaces or tabs, exclude patterns (validated as gitignore lines). A damaged file
is reported and left unchanged.
